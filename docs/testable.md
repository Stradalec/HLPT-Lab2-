# Анализ тестопригодности
## Не требует тестов:

ExitCode.kt, Action.kt (это просто enum);

IAuthService, IPermissionManager, IResource - интерфейсы;

MockData - просто класс с выдуманными тестовыми данными;

UserData - это data class;

## Требует тестов:

AuthService - тестировать функции getHash (бросать туда неверные значения по типу данных, несоответствующие друг другу пары пользователь/соль), bytesToHex (проверять работу по превращению масссива байтов в строчку) (Частично выполнено)

PermissionManager - этот класс полного покрытия тестами просит. В grantPermission покидать всякого на вход: несуществующие имена файла, пользователей, действий, в hasPermission попроверять, что будет, если туда придёт несуществущий юзер делать несуществующее действие. (Частично выполнено)

Resource. Проверяем на входе в addChild то, что добавленный ресурс существует, проверяем то, правильный ли ресурс вернул getChild, проверяем, строка ли путь, который поступил в findByPath, проверять, правильный ли элемент удалился через remove, проверять, все ли ресурсы вернулись при getAll (допустим, мы будем знать их число заранее) (Частично выполнено)

CommandHandler - проверить корректность парсинга параметров. Придётся жёстко замокать authService: IAuthService, permissionManager: IPermissionManager users: Map<String, UserData>, root: Resource, благо есть MockData и отдельные классы (надо будет подумать, как их подцепить), проверить, что volume число и прочее.

## Команда запуска тестов из консоли:
java -jar libs/junit-platform-console-standalone.jar --class-path app.jar --select-class ResourceTests

(Вместо ResourceTests можно назначить другой класс)
Делать только после выполнения compileWithTests.sh!
